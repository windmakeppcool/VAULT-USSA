# VAULT 配置台改造方案

> 参考工程：`VAULT模块化收纳指南（带三维图配色功能）/system/`
> 改造对象：`configurator/`（当前 STL 配置台）
> 日期：2026-10-23
> 约束：保持纯静态、无构建链，继续支持本地 HTTP 服务与 `file://` 两种打开方式。

---

## 1. 改造目标

1. **把参考工程的三维配色能力移植到当前配置台**：预设耗材配色、单件染色、自定义方案、方案持久化，并与打印清单 / CSV 联动。
2. **提升组合预览的可读性**：使用参考工程的姿态数据，显示部件标签，支持点击拾取，并让滑轨、锁、铰链等小件也进入预览。
3. **吸收参考工程的现成资产与内容**：723 张模型缩略图、手册分页图、13 组场景组合、分步组装与安装改装文案。
4. **不整体替换当前 UI**：沿用现有「纸张 + 工程图」视觉与三栏结构，只做增量模块。

当前关键限制：

- `assembly.js` 只渲染 `box / module / roof / baseplate / facade` 五类（`app.js` 的 `updateAssemblyPreview` 也做了同样的过滤）。
- 材质按类别共享（`materialFor(category)`），同一类别所有件颜色一致，且没有对外配色 API。
- 单件预览与组合预览都没有颜色控制。
- 部件库是纯文字行，没有缩略图。

## 4. 核心设计

### 4.1 统一「部位配色键」

配色、清单、3D、CSV 共用同一个 `colorKey`，避免各模块各用一套分类。

**第一优先级：按文件名识别细件**

| 文件名特征 | colorKey |
| --- | --- |
| `Springs` | `springs` |
| `Latch` | `latch` |
| `Runner Stopper` | `stopper` |
| `Runner Guides` | `guides` |
| `Runner Slides` | `slides` |
| `Rails` | `rails` |
| `Lock Holder` | `lockholder` |
| `LOCK INNER PART` | `lockinner` |
| `LOCK OUTER PART` | `lockouter` |
| `PINS FOR 1 LOCK` | `pins` |
| `Rods` | `rods` |
| `Key` / `Key Cap` | `lock` |
| `Facade Cap` / `Label` | `facade` |

| 当前 `c` | colorKey |
| --- | --- |
| `box` | `box` |
| `module` | `module` |
| `roof` | `roof` |
| `baseplate` | `baseplate` |

| `rail` / `runner` / `accessory` / `support` | `rails` |
| `divider` | `divider` |

| `rod` | `rods` |

当前 `state` 增加：

```js
colors: {},              // { module:'#d8dad8', box:'#444744', ... }

customColors: {},         // 自定义方案 { id: { name, colors } }

```

持久化：

- 配置状态继续写入 `vault-ussat-config-v1`。
- 自定义配色方案单独写入 `vault-ussat-color-schemes-v1`，避免与清单方案互相污染。

### 4.3 3D 渲染层改造

`assembly.js` 从「类别材质」改为「每件独立材质」：

- `view.parts` 中每项保存 `{ group, mesh, colorKey, baseColor, category, name }`。
- `materialFor` 不再缓存并共享，改为每件创建（或按 `colorKey` 克隆）。
- 新增对外 API：

```js
window.VaultAssembly = {
  update(parts, options),
  setColors(colors),          // 整套预设切换
  paintPart(colorKey, hex),   // 单件染色
  resetColors(),              // 恢复当前预设
  setDyeing(enabled),         // 染色模式（点击即上色）
  onPick(fn),                 // 点击 / 悬停回调
  highlight(colorKey),        // 选中强调
  idle(message)
};
```

关键实现点：

- 选中强调只改 `emissive`，不改 `baseColor`，避免破坏配色。
- `material.needsUpdate = true`，换色后立即重绘。
- 重建场景时释放旧材质；保留现有三角形上限与缓存策略。
- 染色模式关闭后，点击部件只做定位 / 高亮，不再改色。

在 `#assembly-preview` 的 `.ap-explode` 下方新增可折叠「配色工作台」：

### 4.5 清单与导出联动

- BOM 每行增加颜色圆点与颜色名（或 hex）。
- 清单底部新增「耗材颜色汇总」：颜色 / 文件数 / 件数，不估算克重。
- CSV 增加 `颜色` 列，放在 `数量` 之后。
- 新增「复制配色清单」：按颜色分组输出文本，便于 AMS / 多色打印排料。
- 新增「导出配色 JSON / 导入配色 JSON」，用于跨设备迁移。

## 5. 分阶段实施

### 阶段 0：数据与资产导入（P0，无 UI 风险）

本期只做最小集：

1. 新增 `configurator/tools/import_reference.py`：
   - 读取参考工程 `assets/models.json`，用 `originalPath` 与当前 manifest 的 `p` 精确对齐，生成 `configurator/data/vault-3d.js`（`path -> { refId }`），供配色面板取 webp 缩略图。
   - 输出未匹配清单，便于人工核对。
2. 复制 `assets/previews/*.webp` 到 `configurator/assets/previews/`（3.0 MB）。
3. 不复制 `*.vmesh.gz`（183.4 MB）、`*.js` 网格（244.5 MB）与手册分页图；阶段 3–4 需要时再补。

验收：脚本可重复运行；映射覆盖率 ≥ 99%；manifest 与现有功能不变。

### 阶段 1：清单配色联动（P0）

1. 新增 `data/palettes.js`，引入 5 套预设与 10 色色板。
2. `app.js` 增加 `colorKeyFor(e)`、`state.colors`、`state.activeSchemeId`。
3. BOM 行显示色块；CSV 增加颜色列；底部增加耗材颜色汇总。
4. 方案保存 / 读取时一并保存 `colors` 与预设 ID。
5. `styles.css` 增加色块、汇总、配色方案的样式。

验收：不依赖 3D 也能看到清单颜色；刷新后保持；原有 BOM 数量、状态、CSV 字段不回归。

### 阶段 2：三维配色工作台（P0，核心）

1. `assembly.js` 改为每件独立材质，新增 §4.3 的 API。
2. `index.html` 在预览侧栏加入配色面板。
3. `preview.css` 增加色板、部位列表、折叠抽屉样式。
4. `app.js` 绑定：
   - 预设切换 → `setColors`
   - 色板选择 → `activeBrushColor`
   - 点击部位列表 → `paintPart`
   - 点击 3D 部件 → 染色模式时上色，否则高亮 / 定位
   - 保存 / 恢复 / 导出 / 导入
5. 部位列表根据 `currentParts()` 动态生成，只显示当前组合存在的部位。

验收：

- 切换预设时 3D、部位列表、BOM 色块同时更新。
- 染色模式下点 3D 件或列表，只改该部位颜色；关闭后点击不再误改色。
- 保存自定义方案后，下拉出现并可切换；恢复默认回到经典工程配色。
- 切换规格 / 模式后配色保持，新加入的件自动继承当前配色。

### 阶段 3：装配视图升级（P1，后续）

> 本期不做，数据结构预留。

1. `assembly.js` 使用 `vault-3d.js` 中的姿态矩阵，替换当前按类别堆叠的近似布局。
2. 扩展 `RENDER_CATS`：加入 `handle / rail / runner / divider / hinge / lock / rod / backbone / base / feet / wallmount / wheel / accessory / support`。
3. 引入参考工程的标签层与射线拾取：
   - 悬停显示文件名；
   - 点击部件选中并高亮；
   - 标签可点击，联动部件库 / 清单。
4. 保留现有「展开 / 重置 / 正视 / 俯视」控件。
5. 小件按「小件区」网格排列，避免与主体重叠。

验收：姿态与参考工程一致；点击可定位到清单或部件库；大件缺省时不导致整组失败。

### 阶段 4：内容与场景模板（P2，后续）

> 本期不做，`scene-templates.js` 等结构预留。

1. 新增「指南」导航页（`index.html` 增加 rail 入口，新增 `guide.js` / `guide.css`）：
   - 抽屉分步组装（8 步）
   - 储物箱分步组装（7 步）
   - 安装与改装（壁挂 / 桌下 / 移动 / 拉手 / 脚轮）
   - 小零件安装图鉴（锁芯、弹簧、齿条、面板盖、导向件等）
2. 13 组场景模板导入为「方案模板」：一键生成 BOM，并套用三色配色（浅灰主体 / 深灰零件 / 橙色功能件）。
3. 部件库行增加 40–56 px 缩略图，使用 `assets/previews/*.webp`；缩略图加载失败时回退到现有序号块。

验收：模板 BOM 与参考工程数量一致；缩略图不阻塞列表；分步指南可跳转对应 PDF 页码。

### 阶段 5：套件整理 / 3MF（P3，可选）

参考工程的 `kit-plan.js` 提供套件数量规则、支撑标记与打印盘排布，`VAULT-本机3MF助手` 提供本机 3MF 导出。该能力依赖本地 Python 服务，与当前纯静态架构不一致。

建议：

- 若只需要「数量规则 + 支撑标记」，可移植 `kit-plan.js` 的数据规则，不移植 3MF 服务。
- 若需要 3MF 导出，单独立项，不混入本次改造。

## 7. 验收标准

### 功能

1. 5 套预设可切换，3D、部位列表、BOM 色块同步。
2. 自定义色、单件染色、选中高亮互不覆盖。
3. 自定义配色方案可保存、读取、删除、导入、导出。
4. 刷新页面、切换规格、切换模式后配色保持。
5. BOM 与 CSV 带颜色信息；耗材颜色汇总统计正确。
6. 13 组场景模板可一键生成清单并套用三色。
7. 分步组装与安装指引可打开对应手册页。

### 非回归

- 原有 BOM 增删、数量、状态、方案保存 / 读取 / 删除、CSV 导出保持。
- 原有单件 3D 预览、PDF 阅读器、部件库搜索与筛选保持。
- `file://` 打开时仍能显示界面；3D 与本地文件读取的降级提示保持。

### 性能与稳定性

- 配色切换即时生效，不重建几何。
- 组合预览不因新增小件超出三角形上限；超限件按现有策略省略并提示。
- 场景重建后正确释放材质与几何，不出现 WebGL 上下文泄漏。

### 视觉

- 选中态只用自发光 / 描边强调，不覆盖用户配色。
- 色块在浅色纸张背景与深色预览背景上都可辨识。
- 保留当前设计语言，不引入参考工程的绿色主题。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 共享材质导致「改一件、全类变」 | 每件独立材质；同一 `colorKey` 的多件按设计一起变色 |
| 参考工程 ID 与当前路径对不上 | 以 `originalPath` 精匹配，输出未匹配报告；失败时按文件名回退 |
| 配色 hex 与实物耗材色差 | 明确标注「屏幕配色参考」，允许任意自定义色，不宣称色号一致 |
| 小件全部进入 3D 导致卡顿 | 分批加载、三角形上限、超限省略提示；小件按需渲染 |
| 复制 vmesh 体积过大 | 默认只复制 webp（3 MB）；vmesh 仅在明确需要时导入 |
| 中文 / 空格路径 | 继续使用现有 `encodeURIComponent` 路径拼接；不复制参考工程的绝对路径 |
| localStorage 旧数据 | 新增独立 key；读取时校验字段，失败回退默认预设 |
| 染色模式误操作 | 显式开始 / 结束染色；结束后点击只定位 |
